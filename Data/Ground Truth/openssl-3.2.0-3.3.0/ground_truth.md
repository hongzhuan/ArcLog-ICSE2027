# Ground Truth for openssl-3.2.0-3.3.0

## Important Changes

### Algorithm Abstraction Layer (EVP)

- [GT-OPENSSL-3.3.0-0025] Added GCM acceleration implementation based on Zvbb and Zvbc extensions for the RISC-V platform, with priority detection and use at runtime. (Architecture-related: platform compatibility) (PRs: #21923; commits: 003f569)
- [GT-OPENSSL-3.3.0-0026] Added GCM acceleration implementation for RISC-V Zvkg extension, giving priority to vector instructions. (Architecture-related: platform compatibility) (PRs: #21923; commits: 5191bcc)
- [GT-OPENSSL-3.3.0-0037] Added EVP_DigestSqueeze() API, which supports multiple squeezing and outputting data of different lengths for XOF algorithms such as SHAKE. (Architecture-related: public API) (PRs: #7894, #7921, #21443, #21511; commits: 04b5387, 5366490)
- [GT-OPENSSL-3.3.0-0085] Restrict RSA-OAEP related functions to only be valid for RSA keys, and an error will be returned when called with non-RSA keys. (Architecture-related: public API) (PRs: #20319; commits: 0c3eb31)
- [GT-OPENSSL-3.3.0-0088] The EVP_PKEY_get_bits, EVP_PKEY_get_security_bits and EVP_PKEY_get_size functions now add corresponding error entries to the error queue when they fail. (Architecture-related: public API) (PRs: #22459; commits: ae643b3)
- [GT-OPENSSL-3.3.0-0095] Fixed the error in the return value of BLAKE2s's EVP_MD_get_size() so that it correctly returns the output size of BLAKE2s. (Architecture-related: public API) (PRs: #22708, #22710; commits: 11e61b3)
- [GT-OPENSSL-3.3.0-0107] Added necessary null pointer check to EVP_CIPHER API to prevent segfault caused by accessing null pointer when cipher is not initialized. (Architecture-related: public API) (PRs: #22995; commits: 6f22bcd)
- [GT-OPENSSL-3.3.0-0110] Removed support for OSSL_MAC_PARAM_DIGEST_NOINIT and OSSL_MAC_PARAM_DIGEST_ONESHOT flags, marked them as deprecated and ignored, fixed segfault caused by calling EVP_MAC_init. (Architecture-related: public API) (PRs: #23054; commits: 62457fd)
- [GT-OPENSSL-3.3.0-0115] Fixed some block encryption issues in CFB and OFB modes on the s390x platform, using the processed bytes information in the common cipher context instead to ensure that the information can be reset correctly when the context is reinitialized. (Architecture-related: Platform compatibility) (PRs: #23175, #23201; commits: 576a357, f9ccd20)
- [GT-OPENSSL-3.3.0-0124] Fixed error reporting for EVP_PKEY_sign, EVP_PKEY_verify and EVP_PKEY_verify_recover functions when passing in an empty context, now correctly returning an empty parameter error, and returning an operation not supported error when provider support is missing. (Architecture-related: public API) (PRs: #23411; commits: 5a25177)
- [GT-OPENSSL-3.3.0-0129] Fixed the problem that memory corruption may occur due to changes in signature length when passing in a NULL signature buffer in ECDSA_sign, DSA_sign and other functions. Instead, the required signature length is directly returned; at the same time, the SM2 internal signature function returns an error when sig is NULL. (Architecture-related: public API) (PRs: #23529; commits: be47176)
- [GT-OPENSSL-3.3.0-0322] Implemented Pairwise Consistency Test (PCT) for EDDSA, performs signing and verification operations after key generation, and unified it for EVP_PKEY_keygen and EVP_PKEY_pairwise_check. (Architecture-related: public API) (PRs: #23408; commits: fbce6eb)
- [GT-OPENSSL-3.3.0-0390] Based on the code audit results, additional hardening checks have been added to the HPKE internal implementation, including stricter parameter verification, improved error code usage, and optimization of randomly selected functions. (Architecture-related: HPKE interface hardening) (PRs: #22493; commits: a1c0306)
